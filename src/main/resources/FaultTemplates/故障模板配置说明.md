# 故障模板配置说明

## 概述

故障模板文件用于定义各种故障场景的参数配置，每个模板文件都是一个 YAML 格式的配置文件，包含故障类型、影响范围、持续时间等关键信息。

## 配置项说明

### 基本配置项

| 配置项 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| fault.template | string | 是 | 指定使用的故障模板，对应 template 目录下的模板文件 |
| fault.injectpods | string | 是 | 指定受影响的 Pod，支持变量替换 |
| fault.duration | string | 是 | 故障持续时间，格式为数字+s，如 "120s" |

### 特定故障类型配置项

#### 1. CPU 压力故障 (cpu_stress)

| 配置项 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| fault.load | integer | 是 | CPU 负载百分比，取值范围 0-100 |
| fault.workers | integer | 是 | 工作线程数，通常设置为 2 |

示例：
```yaml
fault.duration: 120s
fault.injectpods: $zone.leader-compute-0
fault.load: 50
fault.template: cpu_stress.yaml
fault.workers: 2
```

#### 2. 网络延迟故障 (net_delay)

| 配置项 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| fault.latency | string | 是 | 网络延迟时间，格式为数字+ms，如 "16ms" |

示例：
```yaml
fault.duration: 120s
fault.injectpods: $zone.leader-compute-0
fault.latency: 16ms
fault.template: net_delay.yaml
```

#### 3. 网络丢包故障 (net_loss)

| 配置项 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| fault.loss | string | 是 | 网络丢包率，格式为数字，如 "10" 表示 10% |

示例：
```yaml
fault.duration: 120s
fault.injectpods: $zone.leader-compute-0
fault.loss: "10"
fault.template: net_loss.yaml
```

#### 4. IO 故障 (io_fault)

| 配置项 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| fault.volumePath | string | 是 | IO 故障影响的卷路径 |
| fault.percent | integer | 是 | IO 错误百分比，取值范围 0-100 |

示例：
```yaml
fault.duration: 120s
fault.injectpods: $zone.leader-storage-0
fault.percent: 20
fault.template: io_fault.yaml
fault.volumePath: $storage.volumePath
```

#### 5. Pod 故障 (fail)

该故障类型无额外配置项，仅使用基本配置项。

示例：
```yaml
fault.duration: 120s
fault.injectpods: $zone.leader-compute-0
fault.template: fail.yaml
```

#### 6. 时间偏移故障 (time_shift)

| 配置项 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| fault.offset | string | 是 | 时间偏移量，如 "-10m" 表示时间向后调整10分钟 |

示例：
```yaml
fault.duration: 120s
fault.injectpods: $zone.leader-storage-0
fault.offset: -10m
fault.template: time_shift.yaml
```

## injectpods 配置说明

injectpods 配置项用于指定故障注入的目标 Pod 范围，支持多种变量格式来动态确定目标。

### 变量格式

变量格式为：`$[zone].[zone_type]-[role]-[pod_count]`

各部分说明：

2. `[zone_type]` - 区域类型，可选值：
   - `leader` - 主区域
   - `follower` - 随机从区域
   - `follower.1` - 从区域1
   - `follower.2` - 从区域2
   - `random` - 随机区域
3. `[role]` - 角色类型，可选值：
   - `storage` - 存储节点
   - `compute` - 计算节点
   - `metadata` - 元数据中心
4. `[pod_count]` - Pod 数量，可选值：
   - `0` - 所有满足条件的 Pod
   - `1` - 一个满足条件的 Pod（随机选择）

### 常见变量示例

| 变量 | 说明 |
|------|------|
| `$zone.leader-storage-0` | leader区域的所有存储节点 |
| `$zone.leader-compute-0` | leader区域的所有计算节点 |
| `$zone.leader-storage-1` | leader区域的一个存储节点 |
| `$zone.leader-compute-1` | leader区域的一个计算节点 |
| `$zone.follower.1-storage-0` | follower.1区域的所有存储节点 |
| `$zone.follower.1-compute-1` | follower.1区域的一个计算节点 |
| `$zone.random-storage-0` | 随机区域的所有存储节点 |
| `$zone.random-compute-1` | 随机区域的一个计算节点 |
| `$storage-0` | 所有存储节点 |
| `$compute-1` | 一个计算节点（随机选择） |

### 故障范围生成中的处理逻辑

在故障范围生成过程中，系统会根据 injectpods 变量的值动态解析出实际的 Pod 列表：

1. 解析变量格式，提取 zone_type、role 和 pod_count 信息
2. 根据 zone_type 确定具体的区域：
   - 对于 `leader` 类型，使用配置中指定的 leader 区域
   - 对于 `follower` 类型，使用非 leader 的区域
   - 对于 `random` 类型，随机选择一个区域
3. 根据 role 筛选出该区域中对应角色的 Pod
4. 根据 pod_count 确定最终的 Pod 列表：
   - 当 pod_count 为 0 时，选择所有符合条件的 Pod
   - 当 pod_count 为 1 时，从符合条件的 Pod 中随机选择一个

## 文件命名规范

故障模板文件采用以下命名规范：
```
[区域类型]_zone_[角色]_[影响范围]_[故障类型]_[参数值].yaml
```

示例：
- leader_zone_compute_all_net_delay_latency_016ms.yaml
- random_zone_storage_one_io_fault_percent_020.yaml

各部分含义：
- 区域类型：leader(主区域)、random(随机区域)
- 角色：compute(计算节点)、storage(存储节点)
- 影响范围：all(所有节点)、one(单个节点)
- 故障类型：fail(节点失效)、io_fault(IO故障)、net_delay(网络延迟)、net_loss(网络丢包)、cpu_stress(CPU压力)
- 参数值：具体故障参数，如延迟时间、丢包率等
